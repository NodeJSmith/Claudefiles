> "emit a warning matching the existing `KNOWN_GATE_TYPES` convention (import `GATE_TYPE_TO_STEP` from `gate.py`)"

**Fix:** T03's frontmatter should read `depends_on: ["T01", "T02"]`.

## Warnings

### 1. FR#6 soft-warning test is optional in Prompt but unconditional in Verify

T03's Prompt says: "In `test_direct.py`: ... **If feasible**, also test the soft-validation warning for an out-of-vocabulary value" (T03-output-and-cli.md:51, emphasis added) — phrased as optional.

But T03's `Verify` checklist lists it as a plain, unqualified bullet: "FR#6: ... writing an out-of-vocabulary `pipeline_step` emits a warning" (T03-output-and-cli.md:63), with no "if feasible" qualifier.

This is a soft inconsistency, not a blocking contradiction — the design doc's FR#6 does require the warning behavior itself to exist in the implementation (`direct.py`), just not necessarily that a dedicated test proves it. An executor following the Prompt's "if feasible" language could skip the warning test while still satisfying FR#6's actual code requirement, then find the Verify checklist item technically unsatisfied by test evidence. Recommend tightening the Prompt to make the warning test non-optional, matching the Verify checklist.
